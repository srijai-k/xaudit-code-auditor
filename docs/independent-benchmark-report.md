# XAUDIT Independent Benchmark Report

> **What this is, and how it's different from `docs/benchmark-report.md`.** That report scores the exact corpus (`tests/fixtures/`) that was written alongside the rules, one small file per specific pattern, iterated on until each rule's own tests passed — a regression signal, explicitly disclosed there as not a real-world accuracy measurement. This report scores a **separate** corpus (`tests/independent-benchmark/samples/`): larger, more realistic, multi-concern files — a small Express router, a React dashboard widget, a Node backup script, a config module — with ground truth written down in `manifest.json` by manual security review *before* this script was ever run, and never adjusted afterward to match what the engine produced. That is a real, meaningful difference in independence. It is still not a fully external, third-party benchmark — the same person wrote the rules and this corpus — so treat this as a second, differently-biased data point, not proof of real-world accuracy either.

## Ground truth, file by file

- **`blog-comment-widget.jsx`**: comment.bodyHtml is wrapped directly in DOMPurify.sanitize() at the sink -> low. comment.quotedHtml reaches the sink completely unsanitized -> high. The onClick/onChange/onSubmit handlers must not produce anything.
- **`user-profile-api.js`**: The /users search route builds SQL by string concatenation one variable hop before db.query(sql) -> caught by same-scope tracing. The two $1-parameterized routes must not be flagged.
- **`analytics-loader.js`**: document.write() is called with string concatenation of two function parameters — dynamic, unresolvable to a literal.
- **`config.js`**: The Stripe key literal matches the vendor format regardless of sitting inside a `process.env.X || "literal"` fallback expression — the vendor check runs on any StringLiteral node, independent of its parent shape. DATABASE_URL's postgres:// literal is excluded by the entropy fallback's URL-shape filter and has no vendor/name match, so it correctly produces nothing.
- **`search-page.jsx`**: r.highlightedSnippet is wrapped directly in DOMPurify.sanitize() at the sink -> low. searchIndex.query() must NOT be flagged as SQLi — 'searchIndex' is not a DB-shaped receiver name.
- **`websocket-client.js`**: eval() is called on a non-literal (binary-concatenated) argument. The setTimeout call passes a function reference, not a string, so it must not be flagged.
- **`backup-script.js`**: Both execSync() calls receive a non-literal command (a template literal with interpolation, and a string concatenation).
- **`session-cache.js`**: SESSION_SIGNING_SALT does not match the credential-shaped name pattern (no API_KEY/SECRET/TOKEN/PASSWORD substring), so only the entropy fallback can catch this hardcoded, high-entropy salt value.
- **`build-info.js`**: A 40-char git SHA (canonical hex hash length), a CDN URL, and an npm-style SRI integrity hash are all real, realistic non-secret shapes the entropy fallback was specifically calibrated to exclude. The short SHA and ISO timestamp are low-entropy/short and were also checked directly (see docs/independent-benchmark-report.md and the calibration notes in secrets.ts).
- **`admin-panel.jsx`**: KNOWN, ACCEPTED FALSE POSITIVE: the notice HTML is genuinely a static literal, but it reaches the __html value through two identifier hops (formattedNotice -> noticeHtml), one more than the engine's one-hop tracing can chase. This file also verified a real fix made during this benchmarking pass: dangerouslySetInnerHTML={noticeProps} (the whole props object as a variable, not an inline literal) used to be invisible to this rule outright before that fix — see docs/model-improvements.md.
- **`dashboard-widgets.jsx`**: Ordinary, realistic React data-fetching/rendering code with no dangerous patterns at all — a noise-floor check on a non-trivial file, not just a one-line safe fixture.
- **`order-service.ts`**: Plain TypeScript interfaces/class/business logic, no I/O, no dangerous APIs, no string literals resembling secrets.
- **`github-sync.js`**: The GitHub PAT literal matches the vendor format. The variable holding it ('githubAuth') deliberately does NOT match the generic name-context pattern, so this specifically exercises the vendor-format path, not the name-context path.
- **`report-export.js`**: exportUsersByStatus concatenates raw SQL into sequelize.query() — 'sequelize' is a newly-added qualified receiver name. exportUsersByStatusSafe uses Sequelize's own named-replacement parameterization and must not be flagged.
- **`reports-controller.ts`**: A realistic NestJS controller/service with class, method, and parameter decorators throughout. Before decorators-legacy was added to the parser, this entire file would have failed to parse (a hard parse error) regardless of content. findByStatus concatenates raw SQL into this.dataSource.query() — 'dataSource' is a qualified receiver name, matched via the member-expression property check. findById uses a $1 placeholder and must not be flagged.
- **`legacy-widget.js`**: renderBio calls this.$container.find('.bio').html(bio) with an unsanitized parameter -> high (this file's construction directly surfaced a real gap: the initial jQuery-detection implementation didn't recognize this.$-prefixed-property chains, only bare $-prefixed identifiers — fixed before this was scored, see docs/model-improvements.md). renderSafeSummary wraps the same shape in DOMPurify.sanitize() -> low. The unrelated `report.html(data)` object method must NOT be flagged — 'report' is not jQuery/$-shaped by any of the recognized signals.
- **`auth-middleware.js`**: A leftover dev-only backdoor: password === 'letmein-dev-only' -> flagged. The real login path uses bcrypt.compare(password, user.passwordHash), a CallExpression not a === comparison -> not flagged (the normal, correct case). requireAdmin's req.user.role === 'admin' must NOT be flagged — 'role' is not a credential-shaped name.
- **`jwt-session.js`**: jwt.verify() IS called in this file (in authenticate()), so jwt.decode() in the separate getDisplayName() helper must NOT be flagged, per this rule's own disclosed whole-file (not per-call-site) logic — even though decode() here is used for a different, non-authoritative purpose than where verify() happens. This is the rule doing exactly what it says it does, not a bug.
- **`legacy-token-reader.js`**: jwt.decode() is called and jwt.verify() is never called anywhere in this file -> flagged. Whether an upstream gateway actually validates the token first is invisible to this rule by design (a disclosed, whole-file-only limitation, not a cross-service/cross-file claim).

## Methodology notes

- 19 realistic, multi-concern files, independently authored (not copies or trivial rewordings of `tests/fixtures/` cases), covering all five rule groups plus deliberate noise-floor checks on ordinary, larger, non-trivial "nothing wrong here" code.
- Ground truth was written into `manifest.json` from manual security review of each file, before this scoring script was ever executed against the engine.
- When this benchmark surfaced a real, previously-undocumented gap during its own construction, the fix and the honest before/after are logged in `docs/model-improvements.md`, not silently folded in here.
- This is still not a third-party or externally-sourced dataset. Treat it as a second, differently-biased check, not a claim of real-world accuracy.
- Re-run with `npm run bench:independent` any time a rule changes.
