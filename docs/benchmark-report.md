## Documented blind spots (intentionally included, not failures)

These cases pass their test (the engine does exactly what it says it does) but exist specifically to keep a real limitation visible instead of only testing favorable cases:

- `xss-sanitizer-via-one-hop-variable` (xss, outcome TP): DOMPurify.sanitize() called one step before the sink, through a variable — now recognized as sanitized (severity low) where before the sanitizer call was invisible behind the identifier
- `xss-literal-via-two-hop-variable-still-flagged` (xss, outcome TP): KNOWN FALSE POSITIVE, documented on purpose: same-scope tracing is exactly one hop — a literal passed through a SECOND variable before the sink is still (incorrectly) flagged
- `sqli-concat-via-two-hop-variable-not-caught` (sqli, outcome TN): KNOWN FALSE NEGATIVE, documented on purpose: same-scope tracing is exactly one hop — a value passed through a SECOND variable before reaching the call is still not caught
- `sqli-typeorm-manager-not-qualified` (sqli, outcome TN): KNOWN FALSE NEGATIVE, documented on purpose: bare 'manager' is deliberately NOT in the qualified-receiver list (too generic — cache/state/task managers commonly expose unrelated .query-shaped methods), so TypeORM's manager.query() with real concatenated SQL is missed here
- `secret-firebase-public-config` (secrets, outcome TP): intentionally-public Firebase web config key — must be labelled informational, not a leak, and must NOT be mislabeled as a different vendor
- `exec-dynamic-import-nonliteral-not-flagged` (exec, outcome TN): REVERTED CHECK, documented on purpose (see docs/model-improvements.md): import() with a computed specifier was briefly flagged, then removed after live testing showed it fires on the standard route/locale code-splitting idiom — indistinguishable from this via AST shape alone. Must NOT flag.
- `exec-require-nonliteral-not-flagged` (exec, outcome TN): REVERTED CHECK, documented on purpose (see docs/model-improvements.md): require() with a computed specifier (plugin/strategy-loading idiom) — same reversal, must NOT flag.

## Methodology notes

- This corpus is intentionally narrow (54 cases across the specific rule groups implemented). It is not a general-purpose vulnerability benchmark and must not be cited as one.
- "TN" (true negative) rows are safe fixtures where no finding at/above the case's `forbidSeverity` threshold appeared, as intended.
- Documented false negatives (e.g. `sqli-concat-via-variable-not-caught`) are included in the corpus on purpose, to keep the engine's real limitations visible in this report rather than hidden by only testing cases it handles well.
- Re-run with `npm run bench` any time a rule changes; this file should be regenerated, not hand-edited.
